# T-122 · OTA apagado en producción — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Que el binario de producción no consulte ni aplique actualizaciones OTA, dejando `expo-updates` instalado, y que un test impida reactivarlo sin firma de código.

**Architecture:** Una línea de configuración (`expo.updates.enabled: false` en `app.json`) que `expo prebuild` traduce a `EXUpdatesEnabled = false` en iOS. El test de configuración existente (`configDeUpdates.test.ts`) suma un bloque que exige ese valor. Un ADR registra la decisión.

**Tech Stack:** Expo SDK 54, `expo-updates` ~29, Jest.

**Spec:** `docs/superpowers/specs/2026-09-14-t122-ota-apagado-design.md`

```markdown
---

### ADR-014 · OTA apagado en producción; reactivar exige firma de código

**Estado:** ACEPTADO — PO, 2026-09-14 · T-122 (SEC M-6). Spec: `docs/superpowers/specs/2026-09-14-t122-ota-apagado-design.md`.

#### Contexto
- T-079 configuró EAS Update (`updates.url`, `runtimeVersion: fingerprint`, `channel` por perfil) para poder mandar arreglos de JS sin pasar por la tienda.
- La auditoría #2 (M-6) marcó que, sin firma de código, cualquiera con acceso a la cuenta de Expo publica código que corre en todos los teléfonos sin App Review.
- Ningún archivo de `src/` o `app/` usa la API de `expo-updates`.

#### Decisión
`app.json` → `expo.updates.enabled: false`. La dependencia y el resto de la configuración quedan como están. `src/__tests__/configDeUpdates.test.ts` exige el valor.

#### Descartado
- **Desinstalar `expo-updates`:** cambio de dependencia nativa; el PO pidió lo menos conflictivo para publicar.
- **OTA con firma de código (`codeSigningCertificate`):** custodia y rotación de clave privada sin una necesidad actual.

#### Consecuencias
- Un bug urgente espera un build nuevo y App Review.
- Un `eas update` publicado al canal `production` no se aplica.
- Reactivar OTA exige: `updates.codeSigningCertificate` + `codeSigningMetadata`, un ADR que reemplace a este, y cambiar el test.
```
